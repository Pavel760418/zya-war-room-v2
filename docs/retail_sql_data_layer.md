# Retail SQL data layer (1С ТКПТ → War Room)

## Подтверждённые источники продаж

| Бизнес-поле | SQL |
|-------------|-----|
| Дата продажи | `CAST(DATEADD(year, -2000, dbo._Document156._Date_Time) AS date)` |
| Номер документа / префикс магазина | `dbo._Document156._Number` (nchar) — префикс в Python: `app/domain/store_prefix_map.py` |
| Продажа / возврат | `dbo._Document156._Fld4036` — `2` продажа, `1` возврат |
| Сумма документа | `dbo._Document156._Fld4030` |
| Кассир (доп. разрез) | `dbo._Document156._Fld4020` |
| Строки чека | `dbo._Document156_VT4039` |
| Количество | `VT4039._Fld4042` |
| Сумма строки | `VT4039._Fld4048` |
| Сумма с НДС | `VT4039._Fld4054` |
| Тип цены (кандидат) | `dbo._Document156._Fld4016RRef` → **ожидался** `dbo._Reference92`, но SQL-JOIN на выборке даёт 0 совпадений — уточнить у 1С |

Модули:

- `app/repositories/retail_sales_repository.py`
- `app/domain/store_prefix_map.py`

Ограничения:

- Только `SELECT`, период ≤ 93 дней в репозитории.
- Чистая выручка = сумма `_Fld4030` продаж минус возвраты на уровне **документа**; сверяйте с суммами строк (`_Fld4048`) — при JOIN без осторожности возможен двойной учёт документа.

## Оплаты — только закрытие смены

**Ограничение данных (обязательно для UI и диагностики):**

- В individual чеках (`_Document156`) вид оплаты в SQL **не найден**.
- Разбивка оплат — `dbo._Document119_VT2299`, документ закрытия смены `dbo._Document119`.
- Магазин смены — префикс `dbo._Document119._Number` (та же логика, что у чеков).
- Справочник форм оплаты: `dbo._Reference89` → mapping в Python (`app/domain/payment_form_mapping.py`).
- Метрики War Room подписывать: **«оплаты по закрытиям смен»**, не «форма оплаты чека».

Модуль: `app/repositories/retail_payments_repository.py`

Сопоставление оплат с отдельным чеком **недопустимо** без подтверждённой связи в данных.

## Кандидаты прочих метрик

См. `war_room_sql_integration_candidates.xlsx` (листы «Кандидаты 1С-регистров», «Сводка»).

Примеры кандидатов (не заменяют чеки до сверки):

- Выручка/количество/себестоимость (средний уровень): `dbo._AccumRg6691`
- Альтернативный регистр себестоимости: `dbo._AccumRg6738`
- Складские обороты (низкий уровень): `dbo._AccumRg6601`

Справочник магазинов (высокий, но требует подтверждения связи с префиксом номера): `dbo._Reference64`.
